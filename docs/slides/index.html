Audience

You, if a stranger has to check the run.

This is for you

  • You publish simulation or computational-experiment artifacts.
  • A reviewer should not have to trust a laptop folder, a zip, or a Drive link.
  • You want language for what the bytes allow — and a hard stop after that.

Not the pitch

  • Not “put the simulation on a chain.”
  • Not a score, rank, or lab reputation token.
  • Not a claim that a notarized run is scientifically correct.

The gap

Published runs still live on someone’s laptop.

A reviewer who receives a zip cannot independently fetch the official artifacts, rehash them, and see when that exact file was published — without trusting you.

That is a narrower job than “the science is right,” and a broader one than sha256sum.

Hash tool vs notary

Matching bytes is the start of the sentence.

A hash tool

These files match this digest.

A research notary

  • Which files were admitted, by a recorded allowlist.
  • How many were left out — without printing their names.
  • Whether the design was stamped before the artifacts existed.
  • Whether those exact bytes existed by time T.
  • What you may claim. What you may not.

What it is

The official record, dated, without running a chain.

FarmNotary writes a canonical manifest.json — code identity, config, artifact hashes — optionally pins the directory, and can stamp the content hash via OpenTimestamps. Calendars batch that digest into Bitcoin. No contract, no keys, no gas.

Immutability is not correctness. A manifest can perfectly notarize a wrong result.

Scope

Build what a stranger can check.

In

  • Canonical run and campaign manifests
  • Publish profiles and a privacy denylist
  • Optional remote pin (IPFS pinning service)
  • Keyless Bitcoin timestamp (OpenTimestamps)
  • Claim card, paper-pack appendix, static index
  • GitHub Action and a small Python API

Out

  • Scientific correctness
  • Preventing the file drawer
  • Publishing ballots or individual choices
  • Scores, rankings, protocol identity
  • Operating calendars, contracts, or pin services
  • Running the simulation in the EVM

Official record vs private choice

Nothing is hashed until you say what may leave.

For a consensus experiment: voter or agent choice stays private. The official record is config, code identity, aggregate metrics, winner allocations.

farm-notary manifest --run-dir path/to/run --profile consensus

Checked-in profiles: consensus, rl-sweep, evolution-run. A denylist still drops paths containing ballot, vote, voter, individual_choice, or private. Unmatched files increment a count; their names are never printed.

Solo path · this afternoon

Three commands, then a card.

farm-notary manifest --run-dir path/to/run --profile consensus --config config.json farm-notary verify --run-dir path/to/run farm-notary anchor --run-dir path/to/run --backend ots --pin-remote pinata

Hours later: farm-notary upgrade --run-dir path/to/run completes the Bitcoin attestation. Pending calendars are not L0.

The product

Reviewers read the card, not the exit code.

claim card
level: none — no earned ladder level
next:  L0 — these bytes existed by time T; Bitcoin headers not verified by this tool (missing: Bitcoin attestation)
•  tamper-evident record           — pass
•  existed by time T               — pending
•  pre-specified design            — missing
•  bitwise reproducible (scoped)   — 6/6, ignored: *.mp4; byte-identical on x86-64 Linux in a pinned environment
•  not claimed: scientific correctness

How a stranger uses it

Missing is not failure.

  1. Fetch the CID, or obtain the run directory another way.
  2. Run farm-notary verify --run-dir <dir> and read the card.
  3. Only if you trust the recorded commands: add --verify-derived.

Exit 0 means no attempted check failed — not that every claim was earned, and not that the science is right.

Reader ladder

Earn a rung. Do not decorate one.

LevelMeaningWhat it is not
noneNo Bitcoin attestation yet, or the record does not rehash.A failed experiment.
L0These bytes existed by time T. Proof commits to the content hash and carries a Bitcoin-height attestation.Header verification. Use ots verify.
L1Re-execution is specified: command, git SHA, environment fingerprint.A completed re-run.

Pre-specified design

Stamp the plan before the artifacts exist.

farm-notary precommit --config config.json --command "python run.py --out {run_dir}" --backend ots farm-notary manifest --run-dir path/to/run --profile consensus --precommit precommit.json

A timestamp taken after the result is known is not pre-registration. FarmNotary will still stamp the favorable run. It will not call that a pre-specified design.

Showcase · AgentFarm consensus

Re-run the seed. Scope the sentence.

Demonstrated

  • 100 trials, 300 voters, 8 candidates, seed 0.
  • 8/8 artifacts bitwise after the report stopped embedding its output path.
  • Summary statistics recompute from trials.csv.
  • The only sentence the tool may emit: byte-identical on x86-64 Linux in a pinned environment.

Not a claim

  • Cross-hardware bitwise identity.
  • Linux ARM smoke cell: 6/10. macOS ARM: 2/10.
  • A classified byte-diff (path, timestamp, float print, video encoder) is not a science failure.

From sweep to appendix

The figure is a parent record, not a folder.

farm-notary campaign --name consensus-sweep --run-dir runs/seed-0 --run-dir runs/seed-1 --out sweep/ farm-notary paper-pack --campaign sweep/ --out sweep/appendix.md farm-notary index --registry docs/registry.md --campaign sweep/

The appendix carries CID, content hash, Bitcoin attestation or pending, allowlist, unmatched count, precommit hash, and the scoped sentence. Reader ladder is an em dash: do not cite Ln from the PDF.

Cost and publish

Free to stamp. Impossible to unpublish.

Machine

Python ≥ 3.9. Core is stdlib-only: manifest, verify, IPFS client, dry-run.

Live stamp

[ots] extra. Public calendars. No key, no gas, Bitcoin-backed. EAS stays experimental.

Default

CLI anchor and precommit are dry-run. Nothing is hashed until an allowlist is declared. A remote pin has no retract.

Lab path

Drop the Action in. Fail the job if the card fails.

- uses: dooders/FarmNotary@dev
  with:
    phase: notarize
    run-dir: results
    profile: consensus
    pin-remote: pinata
    backend: ots

Recommended: phase: precommit at job start, phase: notarize after the run. Pin @dev or a commit until v0.2.0 is tagged.

What we will not claim

An anchor proves existence, not correctness.

  • No “verified result” badge. No treating a printed Ln as a finding.
  • No scoreboard, trusted-lab registry, or protocol token.
  • No inventory of unpublished runs. Cherry-picking is out of scope; mislabeling a post-hoc stamp is not.
  • The author’s own reproduction is bitwise (scoped), not independently reproduced.
  • Cross-hardware bitwise identity is not a claim.
